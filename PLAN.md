# Конвертер форматов для Windows — план проекта (v2)

Название: **Morphio**.
Платформа: **только Windows 10 (22H2) / Windows 11, x64**. Мак, Linux, веб и мобильные версии не делаем, это упрощает всё: стек, установщик, тестирование.

---

## 1. Идея

Один локальный инструмент вместо десятка сайтов-конвертеров.

- **Конвертер** для всех популярных форматов.
- **Удаление фона** с изображений (нейросеть, офлайн).
- **GIF-студия**: GIF/WebP/APNG из картинок и видео.
- **Всё офлайн**: файлы не покидают компьютер, нет лимитов, рекламы, капч и водяных знаков.

### Чем лучше аналогов
| Проблема сайтов и приложений | Наше решение |
|---|---|
| Загрузка файлов на чужой сервер | Всё локально |
| Лимиты, подписки, водяные знаки | Без лимитов |
| Нужно знать формат и битрейт | Режим "по цели" (Telegram, сайт, печать) |
| Не угадать размер результата | Целевой размер файла + предпросмотр до/после |
| Разрозненные инструменты | Всё в одном + цепочки действий |
| Медленно | Ускорение на видеокарте (NVENC / Quick Sync / AMF, DirectML) |

## 2. Ключевые функции

### 2.1 Конвертер
| Категория | Форматы | Движок |
|---|---|---|
| Изображения | PNG, JPG, WebP, AVIF, HEIC, BMP, TIFF, SVG, ICO, PSD (чтение) | libvips (sharp), ImageMagick |
| Видео | MP4, MKV, MOV, WebM, AVI, GIF | FFmpeg |
| Аудио | MP3, WAV, FLAC, OGG, AAC, M4A | FFmpeg |
| Документы | DOCX, PDF, ODT, RTF, TXT, MD, HTML | Pandoc (+ LibreOffice как необязательный модуль) |
| Данные | XLSX, CSV, JSON, XML, YAML | свои парсеры |
| Книги | EPUB, FB2, MOBI | Pandoc / Calibre-модуль |
| Архивы | ZIP, 7z, TAR (RAR только чтение) | 7-Zip |
| Субтитры, шрифты | SRT/VTT/ASS, TTF/OTF/WOFF2 | свои парсеры, fonttools |

Общее: пакетная обработка, очередь с паузой и прогрессом, пресеты, сохранение или очистка метаданных (GPS и др.).

### 2.2 Режим "по цели"
Пользователь выбирает не формат, а задачу: "Telegram", "Instagram", "для сайта", "для печати", "для почты". Приложение подбирает формат, размер и качество.

### 2.3 Целевой размер файла
"Не больше 8 МБ": автоматический подбор качества (поиск по битрейту/качеству) для видео, изображений, GIF, PDF.

### 2.4 Сравнение до/после
Слайдер до/после, размер файла, метрика потери качества (SSIM/PSNR).

### 2.5 Удаление фона
- Несколько моделей: быстрая, точная (волосы), для товаров, для людей.
- Ручная доработка кистью "стереть / вернуть" (готово), заливка областью (раздел 12).
- Экспорт: PNG/WebP с прозрачностью, цвет, градиент, своя картинка, тень, контур.
- Пакетная обработка (сотни фото товаров).
- Позже: видео и анимация без фона.

### 2.6 GIF-студия
- Из картинок: порядок кадров перетаскиванием, задержка на каждый кадр.
- Из видео: выбор отрезка, fps, размер.
- Редактор: обрезка, реверс, "пинг-понг", смена скорости, текст и стикеры.
- Оптимизация до целевого размера (качественная палитра: gifski или palettegen/paletteuse).
- Экспорт: GIF, анимированный WebP, APNG. Обратно: GIF → кадры.
- Прозрачная анимация (удаление фона у всех кадров).

### 2.7 Цепочки действий (пайплайны)
Например: убрать фон → уменьшить до 512 px → WebP → переименовать по шаблону. Сохраняются как пресеты и применяются к папкам.

### 2.8 Интеграция в Windows (то, что даёт приложению "родной" вид)
- Пункт **"Конвертировать…"** в контекстном меню проводника (правый клик по файлу/папке). В Windows 11 он находится в классическом меню («Показать дополнительные параметры», подробности в 9.6).
- **Следящие папки**: файл попал в папку, автоматически обработан по правилу.
- Перетаскивание файлов и папок, вставка из буфера (Ctrl+V), открытие через "Открыть с помощью".
- Уведомления Windows (Toast) по завершении, прогресс на иконке панели задач, Jump List.
- Автозапуск в трее (по желанию, для следящих папок).
- Тёмная/светлая тема по системной, стиль Fluent (Mica).
- Языки: русский и английский.

### 2.8.1 Ускорение на Windows
- Видео: NVENC (NVIDIA), Quick Sync (Intel), AMF (AMD) с автоопределением.
- Нейросети: ONNX Runtime + **DirectML**, работает на любой видеокарте (NVIDIA/AMD/Intel) без CUDA.
- Если GPU нет, откат на CPU.

### 2.9 ИИ-модули (докачиваются по желанию)
Апскейл (Real-ESRGAN), удаление шума, OCR (сканы → текст), субтитры из аудио (Whisper), удаление объектов с фото.

### 2.10 Приватность
"Работает полностью офлайн" как явный принцип. Оригиналы никогда не перезаписываются без согласия, есть отмена. Очистка метаданных одним переключателем.

## 3. Архитектура

```
UI (React + Fluent-стиль)
        │  IPC
Ядро приложения (Node/TS)
  ├─ Очередь задач (параллелизм, пауза, отмена, прогресс)
  ├─ Реестр конвертеров + граф форматов (поиск маршрута A → B)
  ├─ Пайплайны и пресеты, следящие папки
  └─ Менеджер модулей (докачка моделей и движков)
        │
Движки-плагины: FFmpeg · libvips · Pandoc · 7-Zip · ONNX Runtime (DirectML) · gifski
```

Каждый движок объявляет, что умеет ("вход: heic → выход: jpg"). Новый формат добавляется плагином. Если прямого пути нет, граф строит цепочку, например DOCX → PDF → PNG.

Хранение: настройки, пресеты, журналы, модели и модули в `%APPDATA%\Morphio`, временные файлы в `%TEMP%` с очисткой (при запуске и выходе).

## 4. Технологический стек (под Windows)

**Выбрано: Electron + React + TypeScript** (Electron 45, Vite, sharp, onnxruntime-node с DirectML, FFmpeg как внешняя программа).
- Минус: размер около 150 МБ; решается тем, что тяжёлые модули докачиваются.

Дополнительно:
- Сборка и установщик: electron-builder (NSIS + портативная версия), подробности в 9.1; позже, возможно, winget и Microsoft Store.
- Автообновление (electron-updater) и подпись кода: раздел 9.9.
- Тесты: e2e через Playwright и набор эталонных файлов (9.3); Vitest для отдельных функций.

## 6. Риски и юридическое

- **Лицензии сторонних компонентов:** FFmpeg (GPL-3.0, сборка gyan.dev), Pandoc (GPL-2.0+), LibreOffice (MPL) и др. Список и условия: раздел 9.9. Лицензия самого проекта выбирается в конце (раздел 11).
- **Модели:** ISNet и U²-Net (Apache-2.0), BiRefNet (MIT) можно; RMBG от BRIA не используем (лицензия только для некоммерческого использования).
- **Кодеки:** H.264/HEVC/AAC имеют патентные ограничения; бесплатные открытые проекты обычно распространяют кодировщики, но это юридически серо (это не юридическая консультация).
- **SmartScreen:** неподписанный `.exe` показывает предупреждение; план по подписи и обходу: раздел 9.9.
- **Размер:** тяжёлые модели и движки докачиваются по требованию (9.5, 10.4).
- **Качество удаления фона** на волосах и прозрачных объектах: возможны огрехи; есть кисть, заливка добавится (раздел 12).
- **Честные обещания:** показывать, какие форматы поддерживаются, и расширять постепенно.

### Порядок работ (почему именно так)

| 8 | F. Релиз | автообновление, подпись, релиз 1.0, **выбор лицензии последним** | нужен установщик из этапа A |
### 9.1 Установщик (NSIS) вместо портативного exe
- `electron-builder.yml`: цель `nsis` + вторая цель `portable` (портативную версию оставляем для тех, кому нужно без установки).
- Настройки установщика: `oneClick: false`, `perMachine: false` (ставится в `%LOCALAPPDATA%\Programs\Morphio`, **права администратора не нужны**), выбор папки, ярлыки на рабочем столе и в меню «Пуск», русский язык установщика, показ лицензии, при удалении данные пользователя (`%APPDATA%\Morphio`, модели) не трогаем, но спрашиваем, удалить ли их.
- Имена файлов: `Morphio-Setup-<версия>.exe` и `Morphio-Portable-<версия>.exe`.
- Модель нейросети и модули (Pandoc и др.) в установщик не кладём: размер остаётся около 150 МБ, остальное докачивается кнопкой в приложении в `%APPDATA%\Morphio\models` и `...\modules`.
- Результат: запуск за 1–3 секунды вместо 25 (приложение не распаковывается каждый раз). Портативная версия остаётся медленной, это ограничение формата, в README это написано.
- `rebuild.bat` собирает обе версии; в репозитории те же сборки делает CI.

### 9.2 Запоминание настроек
- Один файл `%APPDATA%\Morphio\settings.json`, пишется из основного процесса (атомарная запись: во временный файл, потом переименование; запись не чаще раза в секунду; версия схемы + миграции).
- Что сохраняем: последняя вкладка, размер и положение окна; настройки каждой вкладки (формат, качество, размер, фон, цвета, порядок GIF, параметры видео/звука, пресеты цепочек, папка сохранения); язык и тема (системная/светлая/тёмная); горячая клавиша; правила следящих папок; галочки «закрывать в трей», «запускать с Windows», «проверять обновления».
- Чего **не** сохраняем: списки файлов и результаты (это рабочее состояние).
- Пресеты цепочек сейчас лежат в `localStorage`: один раз переносим в `settings.json` (и они переживают переустановку).
- Реализация: IPC `settings:get/patch`, в интерфейсе хук `usePersistentState(ключ, значение по умолчанию)`; приложение показывается после загрузки настроек (без «мигания»).
- Кнопка «Сбросить настройки» и «Открыть папку данных» на экране «Настройки».

### Этап E: документы, PDF, книги, «до/после» (сделано 13.11.2026)

- **Слайдер «до/после»** (`compare.ts`, `CompareModal.tsx`): на готовой карточке картинки или видео появляется кнопка «Сравнить». Слева оригинал, справа результат, движок тянется мышью или стрелками, колесо мыши приближает, перетаскивание двигает картинку. Над слайдером размеры файлов и «−79%», внизу оценка словами («Разницы на глаз не видно» … «Сильная потеря качества»), в подсказке числа SSIM и PSNR (считаются по серым копиям до 512 px, без зависимостей). Для видео ползунок «Момент видео» берёт кадры обоих файлов через FFmpeg. Файлы окну отдаются как готовые картинки через IPC (data URL до 1600 px), собственный протокол не понадобился.
- **PDF без внешних программ** (`converters/pdf.ts`): pdf-lib собирает, склеивает и делит документы, pdfjs-dist читает текст и рисует страницы на нативном холсте `@napi-rs/canvas`. Варианты: PDF → TXT, PDF → страницы PNG или JPG (в папку), разделить на страницы, картинка → PDF, **«Склеить в один PDF»** для нескольких картинок и PDF (один результат на все файлы). Пароль PDF вводится в настройках. PDF-скан без текста даёт понятную ошибку: распознавание букв (OCR) пока не делаем.
- **Менеджер модулей** (`modules.ts`, карточка «Дополнительные модули» в «Настройках» и баннер в конвертере): манифест (версия, адрес GitHub, SHA-256, размер, лицензия), кнопка «Скачать» с ходом загрузки, проверка суммы на лету, распаковка 7za, метка `.ok`, удаление. Без нажатия кнопки ничего не скачивается. Модули ищутся в `%APPDATA%\Morphio\modules`, рядом с портативным exe и в папке `modules` проекта.
- **Документы и книги** (`converters/documents.ts`, Pandoc 3.14, GPL-2.0+, 43,6 МБ): DOCX, ODT, RTF, HTML, Markdown, TXT, EPUB, FB2 в любых сочетаниях и в PDF. PDF делается так: Pandoc → HTML со стилем → печать встроенным Chromium (окно скрыто, сеть закрыта, скрипты выключены; LaTeX не нужен). Pandoc запускается в режиме `--sandbox`: он не ходит в интернет и не читает посторонние файлы (внешние картинки из HTML не подтягиваются). Обычный TXT превращается в HTML самим приложением, чтобы звёздочки и решётки не считались разметкой. **MOBI и AZW3** работают через бесплатный Calibre (`ebook-convert`), если он установлен; иначе варианты серые с пояснением.
- Ограничения: из PDF в DOCX вёрстка не сохраняется (есть только текст); DOCX → PDF не такой точный, как в Word (LibreOffice для этого пока не используется); OCR и MOBI без Calibre не поддерживаются.

### Правки после этапа D (13.11.2026)

По просьбе «более лёгкий, понятный и красивый интерфейс, объединить вкладки, довести всё до идеала»:
- **Вкладки объединены: было семь, стало четыре.** «Конвертер», «Любой файл» и «Видео и аудио» стали одним **Конвертером** (`ConvertView.tsx`): файлы любых видов, карточки форматов с подписями, быстрый выбор для видео и звука, настройки только выбранного результата, редкие под «Дополнительно». «Удалить фон» и «Цепочки» объединены в **«Фото и фон»** с переключателем режимов. Остались «GIF-студия» и «Настройки» (внизу панели).
- Единый набор элементов `components/ui.tsx` (сегментный переключатель, выключатель, поле с подписью, раздел) и файл `ui.css`: тот же вид на всех экранах, выключатели вместо флажков, видимый фокус для клавиатуры, учёт «уменьшить анимацию». Экраны удаления фона, цепочек и быстрого окна приведены к тому же виду; список файлов больше не «схлопывается» между баннером и настройками.
- Регистр форматов: «тот же формат» теперь предлагается (сжать видео или картинку, сменить разделитель CSV, пересобрать архив). Для CSV с разделителем «;» десятичная запятая («120,5») читается как число.
- Заодно убраны мёртвые части старых экранов (IPC конвертации картинок и видео, неиспользуемые стили и записи словаря).

### 9.5 Документы, таблицы, книги, архивы

**Единый вход.** Новый реестр форматов (`src/main/registry.ts`): каждый движок объявляет «из каких расширений в какие умеет» и функцию `run`. Функция `getTargets(файлы)` возвращает доступные варианты. Её используют вкладка «Универсальный» (бросил любой файл, выбрал во что), окно по горячей клавише и меню проводника. Существующие вкладки остаются как «специалисты».

| Категория | Форматы | Чем делаем | Заметки |
|---|---|---|---|
| Таблицы и данные | CSV, TSV, XLSX, JSON, XML, YAML | `exceljs` (xlsx), `papaparse` (csv), `yaml`, `fast-xml-parser`; всё MIT/ISC, внутри приложения | определение кодировки CSV (Windows-1251 для русских файлов), разделитель `;` или `,`, XLSX с несколькими листами → по CSV на лист; JSON ↔ CSV для списка объектов |
| Архивы | ZIP, 7z, TAR, TAR.GZ (запаковать и распаковать); GZ, TGZ, BZ2, XZ (распаковать) | `7za.exe` из `7zip-bin` (LGPL, около 1 МБ) | «распаковать», «запаковать» файл или папку (уровень сжатия, пароль), архив → другой архив. **Защита:** запрет `../` и абсолютных путей (zip-slip), лимиты 200 000 файлов и 20 ГБ (zip-bomb), список архива проверяется до распаковки, ничего не запускаем. **Ограничения:** RAR не поддерживается (в `7za.exe` нет RAR-кодека, нужен полный 7-Zip); пароль ZIP только из латинских символов (ограничение 7-Zip), для русского пароля есть 7z |

| Книги | EPUB ↔ DOCX/HTML/MD/TXT, FB2 ↔ EPUB | Pandoc | MOBI/AZW3: только если установлен Calibre (`ebook-convert`), иначе пункт серый с пояснением |

### 9.6 Меню проводника и следящие папки

**Пункт «Конвертировать в Morphio»**
- Windows 11 показывает такие пункты в классическом меню («Показать дополнительные параметры», `Shift+F10`). Новое компактное меню требует отдельного COM-компонента в пакете MSIX, это сильно усложняет, поэтому делаем классический: реестр `HKCU\Software\Classes\SystemFileAssociations\...\shell\Morphio` (на пользователя, без прав администратора).
- Пункты: «Конвертировать в Morphio…» (открывает окно по горячей клавише с этими файлами), позже подменю «В WebP / В JPG / В MP3 / Без фона».
- Включение: галочка в «Настройках» («Добавить в меню проводника»; пишет и убирает ключи, работает и для портативной версии) и автоматически при установке (`installer.nsh`).
- Проблема множественного выбора: Проводник запускает **отдельный процесс на каждый файл**. Решение: `app.requestSingleInstanceLock()` и сбор аргументов `second-instance` в окне 300 мс в один пакет.
- Аргументы командной строки: `Morphio.exe --quick <файлы>` (окно) и `Morphio.exe --convert --to webp <файлы>` (без окна, с уведомлением Windows).

**Следящие папки**
- Правило = папка + что делать (пресет цепочки для изображений или пресет видео/звука) + куда класть результат (по умолчанию подпапка `Morphio-out`, чтобы не зациклиться) + расширения.
- Реализация: `chokidar` (MIT) с ожиданием, пока файл дописан (размер не меняется ~1,5 с), очередь на тех же `JobQueue`, по одному файлу за раз, повтор при ошибке, исключение собственной папки результатов.
- Нужен фоновый режим: значок в трее, галочки «закрывать в трей» и «запускать с Windows» (`setLoginItemSettings`, запуск скрыто `--hidden`).
- Экран «Следящие папки»: список правил, пауза, последняя активность, счётчик обработанных файлов. Уведомление Windows после пачки: «Обработано 12 файлов, сэкономлено 84 МБ».
- Старые файлы в папке при добавлении правила не трогаем (есть кнопка «Обработать то, что уже лежит»).

### 9.7 Слайдер «до/после» (изображения и видео)
- Компонент `CompareSlider`: два изображения друг на друге с движком, общий масштаб и перемещение, подписи «Оригинал 4,2 МБ» и «Результат 0,9 МБ (−78%)».
- **Метрики:** PSNR и SSIM считаем в основном процессе по уменьшенным серым копиям (до 512 px, около 50 строк кода, без новых зависимостей). Выводим человеческим языком: «Потеря качества: незаметна / небольшая / заметная».
- Видео: слайдер времени выбирает момент, кадры оригинала и результата берём через FFmpeg (уже есть `videoPoster`); для точных чисел `ffmpeg -lavfi ssim`.
- Вход: кнопка «Сравнить» на готовой карточке (как «Править» у удаления фона).
- Файлы в окно отдаём через собственный протокол `morphio-file://` с белым списком (только входные и выходные файлы текущей сессии), а не через `file://`.
- Позже: живой предпросмотр размера до конвертации (кодируем первый файл с текущими настройками и показываем цифру).

### 9.10 Горячая клавиша и всплывающее окно быстрой конвертации

**Идея.** Выделили файлы в Проводнике, нажали сочетание (по умолчанию `Ctrl+Shift+X`), поверх всего мгновенно появляется компактное окно (как Spotlight / PowerToys Run). В нём уже видны ваши файлы, нужно нажать одну кнопку или цифру, и результат появляется рядом. Окно само исчезает.

**Откуда берутся файлы (по убыванию удобства):**
1. **Выделение в Проводнике.** В момент нажатия определяем окно Проводника на переднем плане и читаем выделенные файлы через `Shell.Application` (небольшой скрипт PowerShell/COM, 200–400 мс, без нативных модулей).
2. **Буфер обмена:** файлы, скопированные в Проводнике (`Get-Clipboard -Format FileDropList`), или **картинка** (скриншот `Win+Shift+S`): можно сразу убрать фон, сжать, сохранить в PNG/JPG.
3. **Перетаскивание** на окно и вставка `Ctrl+V`.
4. Запуск из меню проводника или командной строки (`--quick <файлы>`).
Если ничего не нашлось, показывается пустая область «Перетащите файлы сюда».

**Что в окне (около 440×340, без рамки, поверх всех окон, закрывается по `Esc` или при потере фокуса, на Windows 11 с акриловым фоном):**
- сверху: превью файлов и подпись «3 файла · 12 МБ · изображения»;
- **умные кнопки по типу файлов** (последний выбор стоит первым):
  - изображения: WebP · JPG · PNG · AVIF · «без фона» · «уменьшить до 1600»;
  - видео: MP4 · GIF · MP3 (только звук) · «до 10 МБ (Discord)»;
  - звук: MP3 · M4A · WAV · FLAC;
  - документы: PDF · DOCX · TXT · MD (после этапа E); таблицы: CSV · XLSX · JSON; архивы: «распаковать» · ZIP · 7z;
  - смесь типов: кнопки сгруппированы по категориям, либо одна готовая цепочка на все;
- **шесть закрепляемых действий** с цифрами 1–6: «хоткей → 2» и готово, без мыши;
- переключатели «качество: мало / средне / лучшее» и «куда: рядом / в папку по умолчанию»;
- прогресс прямо в окне; в конце: «Готово · −62% · [Показать] [Открыть]» и уведомление Windows, окно закрывается через несколько секунд;
- ссылка «Больше настроек» открывает главное окно на нужной вкладке с теми же файлами.

**Как это устроено технически:**
- `globalShortcut.register()` в основном процессе. Если сочетание занято, регистрация вернёт отказ: показываем причину и просим выбрать другое; в «Настройках» поле «нажмите сочетание» с проверкой. Сочетания с клавишей Windows Electron регистрировать не умеет.
- Окно создаётся **заранее скрытым** (второй `BrowserWindow`, маленькая отдельная страница `quick.html` без тяжёлых компонентов), поэтому показывается мгновенно. Позиция: рядом с курсором или по центру сверху, на нужном мониторе (`screen.getCursorScreenPoint()`), не выходя за рабочую область.
- **Работает фоном:** значок в трее (меню «Открыть / Быстрая конвертация / Настройки / Выход»), «закрывать в трей», «запускать с Windows». Фоновый процесс занимает порядка 80–120 МБ памяти; всё это включается галочкой и по умолчанию выключено, пока пользователь не включит «Быстрое окно».
- **Один экземпляр** (`requestSingleInstanceLock`): горячая клавиша принадлежит запущенной копии, повторный запуск просто передаёт ей файлы.
- Конвертация идёт теми же модулями и очередями (`convertImage`, цепочки, удаление фона, `convertMedia`, GIF), поэтому ничего не дублируется. Действие окна = запись «id, название, категория, функция» из реестра форматов (этап C).
- Ограничения: окна с повышенными правами (запущенные от администратора) Проводник читать не даёт; если выделение прочитать не удалось, используется буфер обмена, затем пустое окно.
- Безопасность: окно работает только с локальными файлами, без сети.

**Сделано (этап D, 12.11.2026):** трей, «закрытие в трей», запуск с Windows (в собранном приложении), быстрое окно по сочетанию клавиш (создаётся заранее скрытым; выделение Проводника, затем скопированные файлы, затем скриншот из буфера; перетаскивание на окно; варианты из реестра форматов, цифры 1–9, последний выбор первым; кнопка «Больше настроек» открывает главное окно с теми же файлами), пункт в меню Проводника (файлы и папки, классическое меню), `Morphio.exe --quick`, один экземпляр с объединением файлов за 300 мс, следящие папки (`chokidar`, ожидание дописывания файла, только сама папка без вложенных, результат в `Morphio-out`, итоговое уведомление), экран «Настройки». Проверено: автотесты слежения, меню и чтения выделения; в собранном exe через окно (`--quick`, второй запуск, слежение, регистрация сочетания, запись и удаление пункта в реестре).
**Отличия от замысла:** выделение читает один постоянный скрытый PowerShell (около 60 МБ, ответ за 15–220 мс; без него 1,3 с; запускается только при включённом быстром окне); вместо шести закрепляемых действий работает «последний выбор первым» с цифрами 1–9; переключатели качества и «куда сохранять» в быстром окне не сделаны (используются настройки по умолчанию, остальное через «Больше настроек»); уведомление быстрого окна без прогресса в трее; командная строка `--convert` без окна остаётся этапу G. **Не проверено вручную:** физическое нажатие сочетания клавиш, вид значка в трее, пункт в меню Проводника «вживую», на портативной версии холодный запуск быстрого окна из меню занимает несколько секунд (пока не включён режим «быстрое окно» с предварительным запуском).

**Этапность.** Нужны: хранилище настроек, трей и быстрый запуск (установщик), реестр форматов. MVP: хоткей + буфер/перетаскивание + изображения, видео, звук. Затем выделение в Проводнике, цифры 1–6, документы после этапа E.

### 10.1 Видео: обрезка по времени, поворот, склейка, субтитры, нормализация громкости

Новый экран **«Монтаж»** (рядом с «Видео и аудио»; обычная конвертация остаётся как есть). Все правки
собираются в **один план монтажа**, который превращается в один запуск FFmpeg (без промежуточных файлов).

- **Обрезка по времени.** Лента кадров под плеером (миниатюры по длине ролика, одна команда FFmpeg
  `fps=1/N,scale,tile`), две ручки «от и до» с превью кадра, ввод времени цифрами `мм:сс.д`.
  Два режима: **«Быстро»** (без перекодирования, по ключевым кадрам, мгновенно, но граница может
  сместиться на секунду-две) и **«Точно»** (перекодирование, граница кадр в кадр; по умолчанию, если
  всё равно что-то перекодируется). Несколько отрезков одного ролика: убрать середину.
- **Поворот и отражение.** На 90°/180°/270°, зеркало по горизонтали/вертикали, «исправить ориентацию».
  Быстрый путь: поворот меткой в файле без перекодирования, если контейнер это поддерживает.
  Позже: кадрирование (crop) рамкой.
- **Склейка.** Список клипов с перетаскиванием порядка. Если у всех одинаковые кодеки и параметры, то
  склеиваем без перекодирования (мгновенно). Иначе перекодируем и приводим к общему размеру (с полями),
  частоте кадров и частоте звука; приложение предупредит об этом заранее. Позже: плавные переходы.
- **Субтитры.**
  1. Вшить дорожкой (включается и выключается в плеере): `mov_text` для MP4, SRT/ASS для MKV.
  2. «Вжечь» в картинку (видны везде): фильтр `subtitles` (libass есть в нашей сборке FFmpeg),
     настройки шрифта, размера, цвета, обводки; русские шрифты Windows подхватываются из системной папки.
  3. Достать дорожку субтитров из видео в SRT.
  4. Конвертация SRT ↔ VTT ↔ ASS и сдвиг времени на N секунд.
  5. Автосубтитры из речи: в 10.4.
  Нюанс: в путях к файлам субтитров внутри фильтра FFmpeg двоеточие и обратные слэши нужно экранировать.
- **Нормализация громкости.** По стандарту EBU R128 (`loudnorm`) в два прохода: первый измеряет, второй
  применяет с измеренными значениями. Готовые цели: «Для просмотра −16 LUFS», «Подкаст −16», «YouTube
  −14», свой уровень. Показываем «было −23 LUFS → стало −16 LUFS». Быстрый вариант `dynaudnorm`
  (выравнивает по ходу, для речи). Работает и для звуковых файлов (10.3). Видеодорожка при этом не
  перекодируется, если больше ничего не меняется.
- **Выбор звуковой дорожки** (если их несколько), скорость (быстрее/медленнее), «убрать тишину» как
  необязательные пункты.
- **Тесты:** генерируем ролики FFmpeg (`testsrc2`, тон) и проверяем длительность обрезки с допуском,
  размеры после поворота, число кадров после склейки, уровень громкости до/после (измерение `ebur128`),
  наличие вшитой дорожки и отличие кадра с наложенными субтитрами от кадра без них.
- **Ограничения, о которых скажем честно:** HDR и 10-бит видео при перекодировании в MP4 может
  потерять цвета без тон-маппинга; ролики с переменной частотой кадров (запись экрана) обрезаются
  точнее при перекодировании.

**Сделано (этап G, 10.1, 16.11.2026):** экран «Монтаж» (`MontageView.tsx`, движок `converters/montage.ts`).
- Клипы: добавление кнопкой или перетаскиванием, порядок стрелками. У каждого клипа лента кадров (одна команда FFmpeg `fps,scale,tile`), кадр-превью под ползунком, ручки «начало» и «конец», поля времени «м:сс.д», кнопки «Начало здесь» и «Конец здесь».
- Все правки собираются в **один запуск FFmpeg** (общий `filter_complex`): обрезка (`-ss/-t` перед входом, точно кадр в кадр), склейка (все клипы приводятся к размеру, частоте кадров и звуку первого, недостающий звук заменяется тишиной), поворот на 90/180/270° и отражение, скорость 0,25–4× (`setpts` и цепочка `atempo`), выбор звуковой дорожки, «убрать звук», ограничение высоты кадра, форматы MP4, MKV, WebM, видеокарта.
- **Быстрый режим без перекодирования** (`-c copy`, для одного клипа или склейки одинаковых файлов через concat-demuxer) включается, только если больше ничего не меняется и видео H.264; иначе берётся точный режим. В результате показывается пометка «без перекодирования».
- **Громкость:** EBU R128 в два прохода (`loudnorm`: измерение, затем применение с измеренными значениями, цели −16, −14, −23 LUFS), в результате «громкость −35,2 → −16,0 LUFS»; быстрый вариант `dynaudnorm`.
- **Субтитры:** вшить дорожкой (`mov_text` для MP4, `srt` для MKV, `webvtt` для WebM; работает и в быстром режиме) или вжечь в картинку (`subtitles` с размером, цветом и обводкой; файл переводится в UTF-8, кодировка Windows-1251 определяется сама; FFmpeg запускается в папке с копией, поэтому экранировать пути не нужно). Сдвиг времени в секундах; у одного обрезанного клипа время субтитров пересчитывается от начала отрезка.
- Проверка: 25 модульных тестов на настоящем FFmpeg (длительность, размеры после поворота, склейка, тишина, громкость измеряется `ebur128`, кадр с субтитрами отличается от кадра без них, сдвиг) и 2 сквозных теста окна.
- **Доделано (19.11.2026):** несколько отрезков одного ролика («Разрезать здесь», «Вырезать середину»: куски — обычные клипы списка с тем же файлом, их можно переставлять и удалять); «Убрать тишину» (FFmpeg `silencedetect`, три степени строгости, запас 0,12 с у речи, близкие куски сливаются); кадрирование рамкой (мышью на кадре, пропорции 1:1, 16:9, 9:16, 4:5, рамка считается по первому клипу); плавные переходы между клипами (`xfade` + `acrossfade`, 8 видов, 0,3–2 с, ролик короче на время переходов, у слишком коротких клипов понятная ошибка); быстрый поворот меткой в MP4 без перекодирования (`-display_rotation`, прибавляется к повороту, уже записанному в файле; только один клип и только MP4); извлечение дорожки субтитров из видео и перевод SRT, VTT, ASS и простой текст в обычном конвертере со сдвигом времени (новый вид файлов «субтитры», `converters/subtitles.ts`, `shared/subtitles.ts`).
- Не сделано из 10.1: картинные дорожки субтитров (DVD, Blu-ray: их читают только программы с распознаванием), стили ASS при переводе в другие форматы теряются (так устроен формат).

### 10.2 GIF-студия: текст, стикеры, обрезка кадра, фон у всех кадров

Порядок обработки каждого кадра: **загрузка → обрезка → удаление фона → вписывание в размер →
накладки (текст, стикеры) → кодирование.**

- **Текст.** Слои поверх анимации: шрифт, размер, цвет, обводка и тень (чтобы читалось на любом
  фоне, «мем-стиль»), перетаскивание и поворот на плеере, диапазон кадров «с N по M». Позже:
  простые анимации (появление, бегущая строка).
  **Как рисуем:** текст рендерится в окне приложения через canvas (там доступны все шрифты Windows и
  кириллица), а в основной процесс уходит готовый PNG слоя, который накладывается через sharp. Так мы
  не зависим от шрифтов встроенной библиотеки sharp, которые на Windows ненадёжны.
- **Стикеры.** Свои PNG/WebP/GIF и встроенный набор эмодзи (шрифт Noto Emoji, лицензия OFL; Twemoji
  потребует указания авторства). Перетаскивание, масштаб, поворот, диапазон кадров. Позже: анимированные
  стикеры, совмещаемые по времени с кадрами.
- Слои хранятся в относительных координатах (0–1 от размера кадра), поэтому не зависят от выбранной
  ширины итогового GIF.
- **Обрезка кадра.** Рамка на плеере (свободно, 1:1, 16:9, 9:16, 4:3) применяется ко всем кадрам.
  Отдельно: обрезка по времени (ручки на ленте кадров, удалить кадры с начала и конца) и скорость
  выбранного диапазона.
- **Удаление фона у всех кадров сразу** (прозрачная анимация), движок уже есть:
  - **однотонный фон:** быстро; цвет и допуск определяются **по первому кадру и фиксируются** для всех,
    чтобы они не «плавали»;
  - **нейросеть:** около 0,25–0,5 с на кадр на видеокарте (замер на ISNet; 100 кадров ≈ 30–60 с),
    показываем оценку, прогресс и «Остановить». Покадровые маски мерцают, поэтому добавляем
    **сглаживание по времени** (маска усредняется с соседними кадрами) и опцию «стабилизировать края»;
  - **формат результата:** в GIF прозрачность только «есть/нет», края получаются рваными. Поэтому
    предлагаем анимированный **WebP или APNG** (мягкие края; APNG собираем через FFmpeg, sharp его не
    пишет), а для GIF готовим края с заливкой цветом будущего фона («матовый» режим) и предупреждаем.
- **Тесты:** наложение текста на эталонный кадр (сверка пикселей), стабильность маски на серии кадров
  (разница между соседними кадрами ниже порога), прозрачность в результирующем WebP/APNG.

**Сделано (этап G, 10.2, 19.11.2026):** GIF-студия+ (`converters/gif.ts`, `converters/gifLayers.ts`, `GifCanvas.tsx`, `GifTools.tsx`, `gifLayers.ts` в окне).
- **Порядок обработки каждого кадра:** загрузка → обрезка рамкой → удаление фона → вписывание → текст и стикеры → кодирование (как в плане).
- **Текст и стикеры.** Слои рисует **окно** через canvas (все шрифты Windows, кириллица) и отдаёт готовый PNG; основной процесс накладывает его на каждый кадр в относительных координатах (доли кадра), поэтому результат не зависит от итоговой ширины. У текста: шрифт (Impact, Arial Black, Segoe UI и др.), кегль, цвет, жирный и курсив, **обводка** (цвет и толщина) и тень, несколько строк. Стикеры: 48 эмодзи (системный шрифт эмодзи Windows) и свои PNG/WebP/GIF (берётся первый кадр). На кадре слои **двигаются мышью**, за угол меняется размер (текст при этом перерисовывается чётко), за верхнюю точку поворот с прилипанием к 0/90/180°; есть непрозрачность, порядок слоёв и **диапазон кадров** «с … по …» (кнопки «с текущего» и «по текущий»). Диапазон считается по исходным кадрам, поэтому при порядке «туда-обратно» слой на повторах ведёт себя так же.
- **Обрезка рамкой** одна для всех кадров: пресеты 1:1, 16:9, 9:16, 4:3 или свободно, рамку двигают и тянут за углы (с блокировкой пропорций); холст берёт размер первого обрезанного кадра. **Обрезка по времени:** «обрезать до этого кадра» и «после этого кадра».
- **Удаление фона у всех кадров.** Однотонный фон: цвет и допуск определяются **по первому кадру и фиксируются** (не «плавают»); нейросеть (ISNet): маски всех кадров считаются сначала и **сглаживаются по времени** (веса 1-2-1), чтобы края не мерцали. Режим «авто» выбирает однотонный, если фон ровный. Формат результата: **WebP** (мягкие края), **APNG** (новый формат, собирает FFmpeg по списку кадров с их задержками) или GIF с «матовыми» краями (полупрозрачные пиксели смешиваются с цветом будущего фона и режутся по половине, без светлой каймы) и честным предупреждением.
- Проверка: 19 модульных тестов (рамка, наложение пикселей, поворот, непрозрачность, диапазоны, туда-обратно, обрезка вместе со слоем, фон на нескольких кадрах, устойчивость цвета фона, матовые края, нейросеть на настоящей модели, APNG: число кадров и прозрачность) и 4 сквозных теста окна (перетаскивание слоя мышью, проверка пикселей готового файла, APNG, обрезка кадров, порядок слоёв).
- **Доделано (19.11.2026):** анимации слоёв (появление, исчезновение, мигание, выезд снизу, бегущая строка; считаются по номеру кадра общей функцией `shared/layerAnim.ts`, поэтому окно и готовый файл показывают одно и то же); скорость части кадров (диапазоны «кадры с … по … ×2», влияют на задержки); рамка и слои в экспорте «Кадры в PNG».
- Не сделано из 10.2: анимированные стикеры из GIF (стикер остаётся картинкой, но его можно двигать теми же анимациями); эмодзи берутся из системного шрифта Windows, а не из набора Noto Emoji (нужен отдельный шрифт на 10 МБ с лицензией OFL: скачивание только с вашего согласия).

### 10.3 Цепочки: шаги для видео и звука

Сейчас цепочка умеет только картинки. Обобщаем модель: **цепочка = вид файла + упорядоченный список шагов.**

- Виды: картинки (есть), видео, звук. Один **универсальный пресет** может содержать три ветки («для
  картинок / видео / звука»); на любой файл применяется подходящая ветка. Этот же формат использует
  командная строка, следящие папки и окно по горячей клавише.
- Шаги видео: обрезка, поворот, масштаб, нормализация громкости, убрать звук, субтитры, формат и
  качество, лимит размера, шаблон имени. Шаги звука: обрезка тишины, нормализация громкости, формат и
  битрейт, теги, шаблон имени.
- Все шаги складываются в **один** запуск FFmpeg (общий граф фильтров), поэтому качество не теряется на
  промежуточных кодированиях и быстро.
- Новые готовые цепочки: «Подкаст: −16 LUFS → MP3 128», «Видео для сторис 9:16 до 30 МБ»,
  «Видео для Telegram до 50 МБ», «Фонотека: FLAC с тегами», «Скринкаст: обрезать → ужать».
- Старые сохранённые пресеты не пропадают: в настройках храним версию схемы и мигрируем автоматически.
- Зависит от 10.1 (нужны шаги обрезки, поворота, громкости).

**Сделано (этап G, 10.3, 16.11.2026):** цепочки для видео и звука (`shared/chains.ts`, `chains.ts`, `converters/audioChain.ts`, экран «Фото и фон → Цепочки»).
- Цепочка теперь состоит из трёх **веток**: картинки, видео, звук. Файл идёт через ветку своего вида, одна цепочка обрабатывает смешанную папку. У каждой ветки свой выключатель «Обрабатывать» и свой шаблон имени (`{name}`, `{n}`, `{date}`, `{format}`). Если для вида файла ветка выключена, файл получает понятную ошибку, а не пропадает молча.
- **Видео:** срез секунд с начала и с конца, поворот, **соотношение сторон** 9:16, 1:1, 4:5, 16:9 (обрезать лишнее или добавить поля), убрать звук, громкость по стандарту, формат, размер кадра, **лимит размера в МБ** (битрейт подбирается сам, до трёх попыток), качество. Все шаги идут одним запуском FFmpeg через движок монтажа (в него добавлены `fit`, `targetMB` и своё имя результата).
- **Звук:** убрать тишину в начале и в конце (`silenceremove`), громкость в два прохода до −16, −14 или −23 LUFS, формат (MP3, M4A, WAV, FLAC, OGG, OPUS), битрейт, **теги** сохранить или убрать.
- Готовые цепочки: «Видео для сторис 9:16 до 30 МБ», «Видео для Telegram до 50 МБ», «Скринкаст: обрезать и ужать», «Подкаст: −16 LUFS → MP3 128», «Фонотека: FLAC с тегами» (плюс прежние пять для картинок).
- **Версия схемы:** сохранённые цепочки имеют `version: 2`; старые (только картинки, без версии) открываются как ветка «картинки», а видео и звук в них выключены, поэтому ведут себя как раньше (`migrateChain`, `migratePresets`). Формат общий для окна и будущей командной строки.
- Проверка: 14 модульных тестов (миграция, план видео, обрезка краёв, 9:16, лимит размера, тишина, LUFS, теги, картинка) и 3 сквозных (смешанная папка, цепочка «Подкаст», старые цепочки). Нерешённое: цепочки лежат в хранилище окна (localStorage), в `settings.json` их перенесёт этап A вместе с командной строкой; шаги «субтитры» (файл рядом с роликом: «фильм.srt», «фильм.ru.srt»; дорожкой или в картинку) и «теги» (исполнитель, альбом, жанр, год для всех файлов) добавлены 19.11.2026.

### 10.4 ИИ-модули (по желанию, как модель для удаления фона)

**Основа.** Общий менеджер модулей (этап E): экран «Модули» со списком, размером, лицензией, статусом,
кнопками «Скачать» и «Удалить»; скачивание только по нажатию, с проверкой SHA-256; источники только
официальные релизы и репозитории; работает всё **локально** (ONNX Runtime + DirectML, как удаление фона).
Один тяжёлый ИИ-процесс за раз (очередь), предупреждение о нехватке памяти видеокарты, отмена.
Перед включением каждой модели проверяем лицензию (нельзя брать модели «только для исследований» и
«только некоммерческие», например RMBG).

- **Увеличение фото (апскейл).** Real-ESRGAN (лицензия BSD-3): лёгкая модель `general-x4v3` (несколько
  МБ) и точная `x4plus` (около 64 МБ), для рисунков и аниме отдельная. ×2 и ×4. Большие картинки
  обрабатываем **плитками** (256–512 px с перекрытием и плавным смешиванием краёв), иначе не хватит памяти
  видеокарты; прозрачность увеличиваем отдельным путём. Прогресс по плиткам, потолок размера входа.
  Также в том же модуле: убрать шум и артефакты JPEG. Важно: перед включением проверить источник и
  лицензию именно того ONNX-файла, который будем скачивать.
  Тест: уменьшаем эталонное изображение, увеличиваем нейросетью и обычным способом, сравниваем PSNR/SSIM.
- **Распознавание текста (OCR) со сканов.** Три варианта, выбираем по результатам проверки:
  1. **Tesseract.js** (Apache-2.0, WASM, языки по ~10–15 МБ, офлайн после скачивания): предсказуемо и
     одинаково на всех компьютерах. **Рекомендую начать с него.**
  2. **Windows OCR** (встроено в Windows 10/11, ничего скачивать не нужно, зависит от установленных
     языков): как «быстрый режим» позже.
  3. PaddleOCR (ONNX, точнее, но сложнее и тяжелее): если качества Tesseract не хватит.
  Вход: картинки и PDF-сканы (страницы рисуем через `pdfjs-dist`). Выход: TXT, Markdown и **PDF с
  текстовым слоем** (ищется и копируется). Предобработка: выпрямление, контраст, определение ориентации
  страницы, выбор языков (русский + английский по умолчанию).
- **Субтитры из речи (Whisper).** `whisper.cpp` (MIT) как отдельная программа-модуль, как FFmpeg:
  - модели ggml: `tiny` (около 75 МБ), `base` (около 142 МБ), `small` (около 466 МБ; для русского
    уже заметно лучше), `medium` (около 1,5 ГБ), `large` (около 3 ГБ); выбираем по размеру и точности,
    по умолчанию `base`/`small`; источник и контрольные суммы фиксируем в манифесте модулей;
  - конвейер: FFmpeg → моно WAV 16 кГц → whisper → SRT/VTT/TXT; язык «авто» или заданный; прогресс из
    вывода программы; оценка времени до запуска;
  - ускорение: сборка с Vulkan работает на NVIDIA/AMD/Intel, иначе процессор (на процессоре `small`
    примерно в режиме реального времени, замерим);
  - после распознавания: простой редактор субтитров (таблица «время / текст», правка, сдвиг), затем
    «вшить» или «вжечь» через 10.1. Перевод субтитров не делаем (офлайн-перевод это отдельная большая тема).
  - Тест: короткая запись с известной фразой и проверка, что она есть в результате.

**Сделано (этап G, 10.5, 17.11.2026):** командная строка (`cli.ts`, `cli-node.ts`, `morphio.cmd`, `scripts/cli.cjs`).

### 10.5 Командная строка (`morphio convert ...`)

**Как запускать.** Приложение окошечное, и из него в консоль ничего не выводится. Решение: рядом с
`Morphio.exe` кладём лёгкий `morphio.cmd` (в установщике по желанию добавляется в `PATH`), который
запускает тот же Electron в режиме **Node** (`ELECTRON_RUN_AS_NODE`) на скрипт командной строки с
обычным выводом. Конвертеры (sharp, FFmpeg, ONNX, 7-Zip) работают без окна, мы это уже проверяли.
Для нескольких задач, которым нужен Electron (PDF через встроенный Chromium), используется скрытый
режим `--headless` с тем же интерфейсом; выбор автоматический.

**Команды (набросок):**
```
morphio convert <файлы|папки|маски> --to webp [--quality 80] [--width 1600] [--out <папка>] [--strip-metadata]
morphio remove-bg <файлы> [--method auto|solid|ai] [--bg transparent|#ffffff] [--format png]
morphio gif <кадры|видео> [--fps 12] [--width 480] [--start 1.5 --duration 3] [--max-size 2MB] -o out.gif
morphio media <файлы> --to mp4 [--preset discord] [--max-size 10MB] [--gpu auto] [--normalize -16] [--trim 00:10-00:25] [--rotate 90]
morphio run <имя пресета | файл.json> <файлы>      # цепочка из GUI
morphio presets list
morphio modules list | install <имя> [--yes]
morphio doctor                                      # версии, FFmpeg, видеокарта, модули, пути настроек
morphio --version | --help
```
**Поведение:**
- Выход: пути созданных файлов в stdout (по одному на строку, удобно для пайпов), прогресс и сообщения
  в stderr (полоса прогресса; `--quiet` отключает); `--json` для машиночитаемого вывода; `--dry-run`
  показывает, что будет сделано.
- Коды завершения: `0` успех, `1` ошибка, `2` неверные аргументы, `3` часть файлов обработана с ошибками.

## 12. Инструмент «Заливка» в редакторе удаления фона (утверждено 12.11.2026)

Идея: как «ведёрко» в Paint, но для удаления фона. Выбрали цвет, кликнули левой кнопкой, и эта область
стала прозрачной. Возврат делается привычными **Ctrl+Z / Ctrl+Y**.

### 12.1 Принятые решения

| № | Вопрос | Решение |
|---|---|---|
| 1 | Откуда берётся цвет и какая область | **Оба варианта.** Источник цвета: «под курсором» или «из пипетки». Область: «смежные» или «везде». По умолчанию: **под курсором + смежные** (как в Paint) |
| 2 | Кнопки мыши | **Левая кнопка только убирает.** Возвращать правой кнопкой не нужно: возврат это **Ctrl+Z** (отменить) и **Ctrl+Y** (повторить), как привычно. Остальное управление не меняется: колесо мыши масштабирует, правая кнопка или пробел двигают картинку, у кисти остаются режимы «Стереть» и «Вернуть» |
| 3 | Подсветка при наведении | **Включена по умолчанию** (можно выключить) |
| 4 | Где доступно | **Сначала только в редакторе маски** (кнопка «Править кистью» на готовой карточке). До обработки на главном экране не делаем |
| 5 | Допуск по умолчанию | **Средний**, меняется ползунком и клавишами `[` и `]` (как размер кисти) |

### 12.2 Как это выглядит для пользователя
- В панели инструментов редактора рядом с «Кисть» появляется **«Заливка»** (горячая клавиша **G**).
- Параметры инструмента:
  - **Допуск**: насколько похожий цвет считать тем же;
  - **Цвет:** «под курсором» или «из пипетки» (кнопка «Пипетка» в панели инструмента берёт цвет с картинки);
  - **Область:** «смежные» или «везде»;
  - **Мягкость краёв**;
  - **Подсветка** при наведении (вкл/выкл).
- **Подсветка:** при наведении курсора область, которую заберёт заливка, закрашивается полупрозрачным
  цветом, поэтому видно результат до клика.
- **Левый клик** убирает область (становится прозрачной).
- **Ctrl+Z / Ctrl+Y** отменяют и повторяют шаги по порядку: и заливки, и мазки кисти в одной истории.
- Два типовых сценария:
  - *«Как в Paint»:* кликнул по розовой области, она исчезла (цвет под курсором, смежные);
  - *«Убить выбранный цвет»:* пипеткой выбрали цвет фона, режим «везде», один клик убрал этот цвет по
    всей картинке, включая «дырки» внутри предметов.
- Правила, чтобы не было неприятных сюрпризов:
  - клик по уже прозрачной области ничего не делает и не попадает в историю;
  - если допуск слишком большой и заливка «протекла» в объект, это видно по подсветке и исправляется
    отменой;
  - вернуть кусок можно кистью в режиме «Вернуть» или отменой.

### 12.3 Что и как считает заливка
- **Область.** От точки клика (режим «смежные», 4-связность) или по всей картинке («везде») берутся пиксели,
  цвет которых близок к опорному. Расстояние считается в цветовом пространстве **Lab (ΔE)**, оно ближе
  к зрению, чем RGB. Каждый пиксель сравнивается с опорным цветом, а не с соседом.
- **Края без каймы** (самое важное): пиксели на границе области получают **частичную прозрачность** по
  мягкому порогу, а их цвет очищается от фона теми же приёмами, что в режиме «Однотонный фон»
  (разложение смеси «предмет + фон»). Поэтому розовый ореол не остаётся.
- **Результат** считается так: новая прозрачность = минимум из текущей и значения заливки. Заливка
  никогда не делает уже прозрачное снова видимым.
- **Скорость** (оценка, замерим при реализации): заливка 12-мегапиксельного фото около 100–300 мс;
  подсветка при наведении считается по уменьшенной копии (до 1600 px) и занимает единицы миллисекунд.

### 12.4 Как это устроено в коде
- **Одна история правок** вместо одних мазков кисти: `EditOp = BrushStroke | FillOp`. Порядок важен
  (правки не коммутируют), поэтому хранится именно последовательность.
- `FillOp` (всё это несколько чисел, легко передаётся в основной процесс):
  `{ type: 'fill', x, y, tolerance, contiguous, colorSource: 'cursor' | 'pipette', color?, feather }`.
- **Общий алгоритм** лежит в одном файле (`src/shared/regionFill.ts`) и используется и окном (по
  уменьшенной копии, для мгновенной реакции), и основным процессом (по полному разрешению при
  сохранении). Так результат на экране и в файле совпадает. Заливка по строкам (scanline) с буфером
  `Int32Array`, без рекурсии.
- **Отмена и повтор:** окно перестраивает маску с нуля, проигрывая историю; заливка стоит мало.
- **Сохранение:** `saveMaskEdit` принимает список `EditOp` (мазки + заливки), применяет их к маске в полном
  разрешении, пишет файл. Результат кэшируется как сейчас (`getCutout`).
- Изменения затрагивают: `src/shared/types.ts` (типы), новый `src/shared/regionFill.ts`,
  `src/main/maskEdit.ts` (применение заливок), `MaskEditor.tsx` (инструмент, панель, подсветка, история),
  `devMock.ts`.

### 12.5 Тесты
- Искусственные изображения: смежная и глобальная заливка, влияние допуска, чистота краёв (нет розового
  ореола), «дырки» внутри предметов при режиме «везде».
- Сверка: результат по уменьшенной копии и по полному размеру отличается не больше допустимого.
- Скорость на 12-мегапиксельном изображении.
- Интерфейс: левый клик, подсветка, Ctrl+Z и Ctrl+Y после смеси мазков и заливок, `[` и `]` меняют допуск
  только когда выбрана заливка.
